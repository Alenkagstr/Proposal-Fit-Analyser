# Proposal Fit Analyser

Рабочее пространство эксперта ITMO Fellowship с самостоятельным дизайном по мотивам сайта программы: чёрно-белая основа, фиолетовые акценты и карточки документов. Локальный сайт для подготовки доказательной справки: требования Research Proposal → опыт кандидата → матрица соответствия, риски и вопросы. Интерфейс на русском, документы могут быть на русском и английском.

## Запуск

Нужны Python 3.12+ и файлы проекта. Node.js, база данных и Docker для этого сайта не нужны.

### 1. Получите проект на свой компьютер

Скачайте версию репозитория, содержащую `app.py`, `requirements.txt` и папку `static`, и откройте терминал в его папке. Если изменения уже опубликованы в GitHub, можно выполнить:

```bash
git clone --branch codex/proposal-fit-site https://github.com/Alenkagstr/Proposal-Fit-Analyser.git
cd Proposal-Fit-Analyser
```

Готовая версия находится в ветке `codex/proposal-fit-site`: откройте эту ветку на GitHub и выберите **Code → Download ZIP**. Распакуйте архив и откройте папку с `app.py`.

### 2. Установите зависимости и запустите сервер

**macOS / Linux:**

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Если команда `python` отсутствует, используйте `python3` для создания окружения.

**Windows, PowerShell:**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Активация окружения не обязательна: команды обращаются к его Python напрямую.

### 3. Откройте сайт

Пока сервер работает, откройте в браузере адрес `http://127.0.0.1:8000` на том же компьютере. Не закрывайте терминал с сервером. Чтобы остановить сервер, нажмите `Ctrl+C`.

**Важно про облако:** сервер, запущенный в облачной среде Codex, слушает localhost облачной машины. Ввод адреса `127.0.0.1:8000` в браузере вашего компьютера не откроет облачный сервер. Для обычного локального использования запустите проект на своём компьютере по шагам выше. В этой onboarding-среде публичный предпросмотр не предоставляется.

При ошибке «address already in use» остановите ранее запущенный сервер либо замените порт в команде на `8001` и откройте соответствующий адрес.

### 4. Попробуйте анализ

1. Загрузите CV и Research Proposal, а также отдельную **заявку / анкету кандидата**, если она есть (PDF, DOCX, XLSX, TXT, MD, CSV до 8 МБ). Кликните по кругу CV, Заявка или Proposal, чтобы выбрать файл. Распознанный текст скрыт и используется для анализа. Заявка дополняет CV и не является Research Proposal. Для сканов нужен предварительный OCR.
2. При необходимости добавьте имя, ORCID / Scopus / Google Scholar и дополнительные сведения: публикации, гранты, оборудование, проекты, партнёров.
3. Выберите режим и запустите сопоставление. Кнопка «Попробовать пример» заполняет учебные материалы, анализ выполняется по ним.
4. Просмотрите статусы и разверните доказательства с исходными цитатами; просмотрите вкладку «Ссылки» и экспортируйте Excel (6 листов, включая «Ссылки»), Markdown или JSON.
5. «Удалить анализ» удаляет результат на сервере и очищает поля текущего браузера.

### 5. Подключите AI при необходимости

Без дополнительных подключений доступен предварительный режим по совпадениям слов. Для смыслового AI-анализа:

1. Получите API-ключ в своём аккаунте Neural Deep.
2. Создайте локальный `.env` рядом с `app.py` и задайте `NEURAL_DEEP_API_KEY` (см. ниже). Перезапустите сервер.
3. Откройте **«Подключение AI · Neural Deep»**. По умолчанию выбрана `qwen3.6-35b-a3b`; также доступны `qwen3.8-27b` и `qwen3.6-fp8`.
4. Выберите модель и нажмите **«Проверить AI»**. Проверка отправляет короткий тест без документов и ждёт не более 30 секунд на запрос к API.
5. После успешной проверки запустите AI-анализ. Доступ к модели зависит от аккаунта и квоты.

Для настройки ключа создайте локальный `.env` рядом с `app.py`. В PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Если `.env` уже существует, откройте его без копирования, чтобы не затереть настройки. Заполните `NEURAL_DEEP_API_KEY=...` своим ключом и сохраните файл. Имя должно быть **`.env`**, а не `.env.txt`; включите отображение расширений в Проводнике. Приложение автоматически читает `.env` при запуске. Переменные, заданные в окружении процесса, имеют приоритет над `.env`. Ключ не добавляйте в Git и не присылайте в чат. После изменения `.env` перезапустите сервер.

`PROPOSAL_MODEL` необязательна: модель по умолчанию — `qwen3.6-35b-a3b`; доступность зависит от аккаунта. Предпочтительно выбрать доступную модель в интерфейсе. Результат выбора через страницу хранится до перезапуска сервера.

В качестве альтернативы можно задать переменные в терминале.

В Bash ключ можно ввести скрыто, без записи самого значения в историю команд:

```bash
read -rsp 'Neural Deep API key: ' NEURAL_DEEP_API_KEY
export NEURAL_DEEP_API_KEY
printf '\n'
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Для PowerShell:

```powershell
$secret = Read-Host 'Neural Deep API key' -AsSecureString
$env:NEURAL_DEEP_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

В облачной среде добавьте ключ через защищённые настройки среды, сохраните настройки и перезапустите приложение. В черновике настройки объявлено необязательное персональное подключение `NEURAL_DEEP_API_KEY` и домен `api.neuraldeep.tech`; для будущих сессий опубликуйте среду после проверки настроек. Не присылайте значение ключа в чат. Локальный `.env` автоматически читается при запуске; в облаке предпочтительнее защищённые настройки среды.

Другие API-ключи (OpenAI, Scopus, SerpAPI) для текущего сайта не нужны. Внешние научные базы пока не подключены: ORCID, Scopus и Google Scholar распознаются как идентификаторы, публикации нужно приложить самостоятельно.

## Режимы

**Предварительный локальный** работает без ключей и сети: делит Proposal на предложения, классифицирует по простым признакам и ищет совпадения слов. Ограничение в 100 пунктов убрано: весь текст обрабатывается без обрезки в пределах общего лимита 120 000 символов на поле. Он не выполняет смысловую оценку, перевод или содержательное выделение компетенций. Совпадения всегда требуют экспертной проверки; их отсутствие не означает отсутствия опыта. Никакие требования автоматически не подтверждаются.

**AI-анализ** переносит конвейер из `agent_colab.ipynb`: структурированное извлечение требований (цели, задачи, методы, компетенции, ресурсы, этапы, результаты), опыта из CV, отдельной заявки и дополнительных материалов, сопоставление, проверка статусов, риски и справка. В `notebook_core.py` сохранены адаптированные функции ноутбука без Colab-загрузок и выполнения ячеек. `app.py` добавляет проверку JSON-схем, дословных цитат, веб-API и экспорт. Исходные промпты и поле `summary_en` оставлены: краткие формулировки AI могут быть на английском, цитаты — на языке оригинала.

Для AI задайте **на сервере** `NEURAL_DEEP_API_KEY` и, при необходимости, `PROPOSAL_MODEL`. Ключ можно задать через интерфейс, локальный `.env` или окружение сервера; значение не возвращается клиенту. Приложение использует `https://api.neuraldeep.tech/v1`; разрешите этот домен в сетевых настройках облачной среды. `.env.example` описывает переменные; файл `.env` автоматически загружается при запуске. В локальной оболочке можно экспортировать переменные перед запуском; в облаке используйте защищённые настройки среды.

В AI-режиме тексты передаются Neural Deep. Без ключа доступен только локальный режим. Реальная доступность модели и тарифа проверяется запросом к провайдеру, не наличием переменной.

Научные идентификаторы распознаются, но внешние базы автоматически **не запрашиваются**. Метрики не подменяются нулями. Публикации нужно предоставить в CV или дополнительных материалах. Коллекторы из ноутбука сохранены как исходная основа для последующей интеграции, но веб-конвейер их не вызывает.

## Заявка и ссылки

Для каждого кандидата загружайте его CV, его заявку и его Research Proposal в отдельные поля. Опыт из заявки передаётся в AI-конвейер как самостоятельный источник «заявка», дополнительные материалы — как другой источник; цитаты проверяются по соответствующему тексту. В одну заявку не следует смешивать материалы нескольких кандидатов.

В PDF сохраняются URI из аннотаций; в DOCX — гиперссылки, включая ссылки под текстом «Google Scholar»; в XLSX — адреса гиперссылок ячеек и статические адреса в формулах HYPERLINK. Список ссылок содержит тип, URL и документ-источник. Он доступен на вкладке «Ссылки», на отдельном листе Excel, в JSON и справке. Само наличие URL не считается подтверждением компетенции. Внешние страницы автоматически не скачиваются.

Сводный Excel вида «Кандидат / Поле / В заявке / В CV» содержит признаки наличия полей, а не их значения. Такой файл не заменяет документы пяти кандидатов: загрузчик объяснит, что нужна исходная заявка одного кандидата. Личные контакты, дата рождения и хобби не являются доказательствами исследовательской компетенции; исходный AI-промпт исключает извлечение телефона, почты, адреса и даты рождения, но документы передаются провайдеру целиком — удаляйте ненужные персональные сведения перед загрузкой.

Анализ выполняет несколько последовательных запросов: до 180 секунд на запрос и бюджет 10 минут на AI-конвейер, без автоматических сетевых повторов. Ошибка показывает этап в центральной карточке; повтор и возврат сохраняют документы. При потере связи повтор проверяет уже запущенное задание. Прямой короткий SDK-запрос в Colab не проверяет весь конвейер и поддержку JSON-схем.

## Если AI недоступен

- **Старая версия не давала выбрать AI:** сервер не видел ключа. Обновите файлы, установите зависимости и подключите ключ через новый блок настроек или `.env`.
- **401:** ключ отклонён; нужен ключ Neural Deep, а не другого провайдера.
- **403:** проверьте доступ аккаунта и сетевое разрешение `api.neuraldeep.tech`.
- **404:** модель или API не найдены; выберите доступную модель.
- **429:** исчерпана квота или лимит; проверьте тариф и баланс, повторите позже.
- **Тайм-аут / ошибка подключения:** проверьте сеть, прокси и доступность провайдера.
- **Некорректный JSON / обрезанный ответ:** попробуйте другую модель или сократите материалы. Система не выдаёт повреждённую матрицу за успешный результат.

Приложение не переключается с AI на локальный режим без вашего выбора. Авторизация и квота не перепроверяются многократными одинаковыми запросами. Первый запрос отправляется без `response_format`: схема передаётся в инструкции, ответ проверяется локально. Резервные форматы используются при некорректном JSON. Строгая схема не требуется для первого запроса. При тайм-ауте карточка показывает модель, тип сбоя, длительность и объём входа; ключ и документы в диагностику не включаются. Если «Проверить AI» работает, а анализ нет, сравните запуск с небольшим фрагментом Proposal.

## Обновление без ZIP и свои правки

Один раз установите [Git for Windows](https://git-scm.com/download/win), откройте новый PowerShell и клонируйте проект в новую папку:

```powershell
git clone --branch codex/proposal-fit-site https://github.com/Alenkagstr/Proposal-Fit-Analyser.git Proposal-Fit-Analyser-git
cd Proposal-Fit-Analyser-git
py -3 dev.py
```

`dev.py` создаёт `.venv`, устанавливает зависимости и запускает сайт на `http://127.0.0.1:8000`. Свой `.env` можно перенести из прежней папки.

В следующих сессиях для получения обновлений и запуска:

```powershell
py -3 dev.py --update
```

Сначала остановите работающий сервер через `Ctrl+C`. Обновление происходит при запуске команды, не постоянно в фоне. При локальных правках, другой ветке или разошедшейся истории скрипт остановится и сохранит вашу работу.

Для своих экспериментов запускайте **без** `--update`: `py -3 dev.py`. Python-файлы перезагружают сервер автоматически; после изменения HTML/CSS/JS обновляйте браузер (`Ctrl+F5`). При перезагрузке Python результаты в памяти и ключ из интерфейса сбрасываются. Изменение `.env` требует ручного перезапуска.

Открывайте папку проекта в VS Code. Краткая [карта файлов](docs/architecture.md). На macOS / Linux вместо `py -3` используйте `python3`. Другой порт: `py -3 dev.py --port 8001`.

## Хранение и ограничения

Для работы на одной локальной машине: авторизации и многопользовательского разграничения доступа нет. Не публикуйте сервер в открытом интернете. Исходные файлы используются во временной папке только для извлечения текста, затем удаляются. Тексты и результаты хранятся в памяти процесса, исчезают при перезапуске. Завершённые результаты старше часа очищаются при следующем запуске анализа; максимум 20 сохранённых результатов, одновременно один анализ. Экспортированные пользователем файлы не удаляются сервером. История не записывается в браузер.

LLM может ошибаться: статус «подтверждено» означает подтверждение представленными материалами, а не независимую верификацию. Система проверяет существование ID доказательств, понижает необоснованные статусы и требует дословных цитат; решение о реализуемости принимает эксперт.

## Проверки

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты покрывают длинные Proposal (160 пунктов без обрезки), отдельный источник заявки, скрытые ссылки PDF/DOCX/XLSX, отказ от использования сводки наличия полей как доказательства, подключение и диагностику AI без раскрытия ключа, резервные форматы JSON, защиту статусов и цитат, выгрузки и удаление. Браузерная проверка охватывает новую страницу, мобильную ширину, вкладку ссылок, загрузку, фильтры и настройку AI с имитацией провайдера. Проверка с имитацией не заменяет реальный запрос к модели.

Проверка цитат учитывает типографские варианты и Unicode-лигатуры. Явно обозначенные пропуски раскрываются до полного фрагмента источника, включая промежуточные оговорки и отрицания. Для AI-сопоставления используются полные проверенные цитаты; перефразирование и совпадение по смыслу сами по себе не подтверждают источник. Статус экспертной проверки сохраняется для конкретной неоднозначности, а не просто узкого названия метода.

AI-анализ дополнен гибридным поиском по исходным документам: локальные многоязычные эмбеддинги MiniLM + BM25 → объединение RRF → оценка контекста моделью → проверка цитат. При первом анализе скачиваются веса (~220 МБ); при необходимости заранее выполните `.venv\Scripts\python.exe retrieval.py --prepare` (Windows) или `.venv/bin/python retrieval.py --prepare` (Linux/macOS). Нужен доступ к Hugging Face, затем векторы вычисляются локально. Новый блок «Исходный фрагмент» показывает контекст и положение в документе. [Методы, подготовка и ограничения](docs/retrieval.md).

Для ускорения независимые AI-запросы выполняются по два одновременно; повторяющиеся фрагменты внутри запроса передаются один раз без обрезки контекста. Частичное подтверждение теперь показывает, что найдено и чего конкретно не хватает; пояснения включены в экспорт.
