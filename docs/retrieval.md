# Поиск доказательств по исходным документам

AI-конвейер использует два источника: первоначально извлечённые проверенные доказательства и прямой поиск в CV, заявке и дополнительных материалах. Поэтому ошибка первого извлечения не исключает фрагмент из последующей оценки.

1. Текст делится преимущественно по абзацам/предложениям на фрагменты до 900 символов с перекрытием около 150 символов. Для каждого сохраняются документ и точные смещения в извлечённом тексте. Это не номера страниц PDF.
2. FastEmbed/ONNX вычисляет локальные 384-мерные векторы моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Модель поддерживает несколько языков, включая русский и английский. Векторы нормируются; смысловая близость вычисляется косинусом.
3. Параллельно BM25 ищет точные термины и сокращения. Используются параметры k1=1.5, b=0.75. Он дополняет семантический поиск для PheWAS, GWAS и названий методов.
4. Reciprocal Rank Fusion объединяет два ранжирования: сумма `1/(60 + место)`; в каждое входит до `max(2*top_k, 12)` результатов. Для каждого требования выбираются до 6 фрагментов. Числа поиска сохраняются для аудита, но не передаются модели как уверенность и не определяют статус.
5. Языковая модель оценивает требования пакетами по 4: получает полный найденный контекст и проверенные доказательства. Она должна различать выполненную работу, владение инструментом, планы и отрицания, объяснять вывод и ссылаться на фрагмент.
6. Код проверяет принадлежность фрагмента этому требованию, присутствие цитаты именно в нём, существование ID и правила силы доказательств. Неизвестная ссылка или выдуманная цитата переводит результат на проверку. Простое упоминание не становится подтверждённым проектным опытом.

В результатах доказательство можно раскрыть до исходного фрагмента с диапазоном символов. Метаданные поиска и происхождение новых доказательств входят в JSON/Excel. Документы и векторы остаются в памяти задания; на диск кэшируются только веса модели в `.model-cache/`. Для смысловой оценки выбранные фрагменты передаются Neural Deep; первоначальное извлечение, как и раньше, также передаёт материалы провайдеру.

## Подготовка модели

После установки зависимостей один раз выполните из папки проекта:

```powershell
.\.venv\Scripts\python.exe retrieval.py --prepare
```

Linux/macOS: `.venv/bin/python retrieval.py --prepare`.

Первая загрузка весов — около 220 МБ, с Hugging Face (включая его CDN/Xet-серверы). API-ключ для неё не нужен. После загрузки вычисление векторов выполняется локально на CPU; GPU и отдельная векторная база не требуются. При запуске анализа модель также подготавливается автоматически. Если загрузка не удалась, сайт показывает ошибку; скрытой подмены гибридного поиска только поиском слов нет. Проверка «Проверить AI» проверяет Neural Deep отдельно от локальной embedding-модели.

## Проверки и ограничения

`.venv/bin/python -m pytest -q` проверяет фрагментацию, BM25/RRF, контролируемые векторы, цитаты, ID, восстановление пропущенного извлечением опыта и существующие функции API. Эти тесты не оценивают качество настоящей нейросети. Для отдельной проверки скачанной модели: `.venv/bin/python tests/embedding_smoke.py` — английский запрос должен найти релевантный русский фрагмент.

Гибридный поиск может пропускать сведения. Top-6 — набор кандидатов, не доказательство полноты просмотра. Сходство не подтверждает опыт; даже проверенная цитата подтверждает только наличие утверждения в документе. Различение намерений и выполненной работы зависит от языковой модели. Полноту поиска и точность статусов нужно измерять на экспертной разметке; проценты точности пока не заявляются. Собственное обучение, внешние научные базы и независимая проверка публикаций не реализованы.
